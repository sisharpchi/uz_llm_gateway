# OPS-002 local qualification record

This is a **single-host functional drill**, not proof of two-node HA or a
production availability/SLA claim. It used disposable `uzllm_load_drill`
PostgreSQL, Redis, two Production-mode Gateway containers, two Workers, TLS
edge, and a deterministic HTTPS provider fixture. No customer data or live
merchant credentials were involved.

- Custom-format backup, SHA-256 verification, isolated `uzllm_restore_drill`
  restore, migration history and wallet/reservation invariant checks passed.
  A non-scratch restore target was refused.
- Recovery integration test distinguished known verified evidence (settled
  once) from unknown evidence (held until deadline, then released without a
  false zero-usage assertion).
- The final k6 run submitted 10 new SSE requests/second for 60 seconds. All
  601 completed with HTTP 200, request ID and `[DONE]`; 0 failed responses,
  0 incomplete streams, 0 dropped iterations. The fixture held each stream
  for 30 seconds. During the run, 301 reservations were simultaneously open.
  Both Gateway replicas served requests. Across the two load runs and one
  smoke request, 1,192 requests had 1,192 settlements and 1,192 usage-charge
  ledger entries; no reservation remained open. Posted wallet balance matched
  the 11-µUSD charge per request.
- Stopping Redis or PostgreSQL separately returned HTTP 503 for new managed
  inference. Stopping one Gateway let the other continue, but the passive edge
  upstream check produced a transient 504 before withdrawing the failed node;
  a streamed POST was never replayed automatically.
- Solution Release build and all tests passed, including 85 persistence
  integration tests. Application/edge Docker builds, Compose parse and Nginx
  TLS configuration checks passed.

The drill did **not** measure the gateway-only first-byte overhead or collect
`uzllm.gateway.active_streams` from an OTLP collector; the 301 concurrent
reservations are a separate server-side indicator, not that metric. A real
two-node deployment, managed PostgreSQL PITR/HA and Redis failover, certificate
rotation, actual RPO/RTO, merchant handshake, and collector-backed NFR-010
latency measurements remain required before a paid production launch. Record
their measured results in the deployment release record.
