# Versioned API artifacts

Task validation evidence: [DX-002 validation](VALIDATION.md).

The [approved DX-004 automation specification](../44_MANAGEMENT_AUTOMATION_API_SPEC.md)
records P2 scope/lifecycle/versioning, not an implemented Bearer scheme or
generated operation. Feature-execution approval/promotion is still required.
Do not use Gateway keys or
headless credentials against existing session-backed Management endpoints;
update these artifacts only with tested future route implementation.

`gateway-v1.openapi.json` and `management-v1.openapi.json` describe the currently
implemented `/v1` and `/management/v1` surfaces (OpenAPI 3.1.1, contract 1.0.0).
Native payment/Telegram callbacks and health endpoints are not Management
client operations; their protocols remain documented in `../11_API_CONTRACTS.md`.
`/v1/responses` exposes the [stateless text subset](../32_RESPONSES_API.md)
and [Responses SSE lifecycle](../33_RESPONSES_SSE.md). `/v1/embeddings` exposes
the [bounded text/float subset](../34_EMBEDDINGS_API.md); conversation storage
remains absent. `ResponsesStreamEvent` describes the named SSE payloads;
serializer-derived SSE fixtures are validated frame-by-frame, not merely as strings.

## Regeneration and drift checks

From the repository root:

```sh
npm ci --prefix frontend/apps
npm run api:generate --prefix frontend/apps
npm run api:check --prefix frontend/apps
npm run api:test --prefix frontend/apps
npm run api:types --prefix frontend/apps
npm run build --prefix frontend/apps
```

Generation uses ASP.NET Core's build-time document generator with synthetic,
process-local configuration. It opens no listeners, connects to no database or
provider, and applies no migrations. Normal builds do not export documents.
Development hosts also expose `/openapi/v1.json`; production hosts do not.
Publish these static artifacts through the documentation site if needed.

`api:check` regenerates into ignored `artifacts/` output and compares the checked-in
documents, examples and generated TypeScript without modifying tracked files.
CI runs this check, schema/negative type fixtures and both frontend builds. A new operation without
an explicit status/security contract fails generation.

## Examples and clients

Runnable [official Node SDK examples](../../examples/node/README.md) use only
these implemented Gateway contracts. They are isolated from browser bundles,
disable automatic retries and require explicit inference billing consent.

`examples.json` is generated by `OpenApiWireContractTests` using the real Gateway
parser/writer and Management serializers/results, with synthetic identities and a
fixed example timestamp. Node tests validate each body against the schema at its
exact operation, status and media type, including replay responses, errors,
nullable unknown usage and money beyond JavaScript's safe integer range.

`frontend/packages/api-client/generated/` is generated with `openapi-typescript`.
The shared client derives wire types, route/method pairs, parameters, bodies and
responses from those files. Session credentials and CSRF remain same-origin and
automatic; no provider or customer secrets belong in examples. Numeric request
properties are documented as JSON numbers; clients must not depend on permissive
server-side numeric-string coercion. Monetary fields follow each endpoint's
actual representation, including decimal strings on billing customer surfaces.

Errors remain endpoint-specific: bare denials, `{error: string}`, Problem Details
and the Gateway OpenAI envelope are not advertised as one universal format.

## Change policy

Review source metadata, documents, examples and client types together. Regenerate
after changing routes, DTOs, statuses, security headers or the bounded chat
contract. A passing drift check does not authorize a breaking wire change:
`../11_API_CONTRACTS.md` section 10 and ADR-004 still require a new versioned path
and at least 180 days of overlap/deprecation notice.

Generator references: [ASP.NET Core OpenAPI generation](https://learn.microsoft.com/aspnet/core/fundamentals/openapi/aspnetcore-openapi?view=aspnetcore-10.0)
and [openapi-typescript Node API](https://openapi-ts.dev/node).
